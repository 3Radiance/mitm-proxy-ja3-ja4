# Подмена TCP-отпечатка (L4)

[English](TCP.md) | [Русский](TCP.ru.md)

Прокси подменяет TCP-отпечаток **исходящих апстрим-соединений**
(TTL, window size, MSS, window scale, флаг DF, порядок TCP-опций),
перехватывая пакеты в очередях Linux Netfilter (NFQUEUE) и переписывая
их до выхода на провод. Это закрывает TCP-слой фингерпринта (сигнатуры
в духе p0f); за TLS (JA3/JA4) и HTTP/2 (Akamai) отвечают свои слои —
см. [TLS](TLS.ru.md) и [HTTP/2](HTTP2.ru.md).

## Как это работает

```
браузер ──TLS──▶ прокси ──TCP+TLS──▶ апстрим
                          │
              SO_MARK на апстрим-сокете (напр. 0x10)
                          │
              mangle/POSTROUTING ──mark 0x10──▶ NFQUEUE
                          │
              ┌───────────┴───────────┐
              │ qnum_syn (только SYN) │  переписываем window/TTL/DF/опции
              │ qnum_tcp (остальное)  │  правим только TTL/DF
              └───────────┬───────────┘
                    Accept, марка стёрта ──▶ на провод
```

1. Каждый апстрим TCP-сокет создаётся с `SO_MARK` из профиля (`mark`)
   (`src/proxy/tcp.rs`). Марка — это внутренняя метадата ядра, на провод
   она не уходит; она только направляет пакет в нужную очередь.
2. Два NFQUEUE-консьюмера крутятся в фоновых тасках (`src/tcp_fingerprint/`):
   - `syn.rs` (`qnum_syn`) — только **SYN без ACK** (открытие соединения).
     Переписывает window size, TTL, флаг DF и пересобирает TCP-опции в
     заданном порядке.
   - `tcp.rs` (`qnum_tcp`) — **всё остальное**. Правит только TTL
     (IPv4) / hop limit (IPv6) и флаг DF. Window и опции в середине
     соединения не трогаются — как у настоящего стека.
3. Каждый забранный из очереди пакет получает вердикт `Accept` — включая
   неподходящие (не-SYN в SYN-очереди, не-TCP, ошибки парсинга). Пакет без
   вердикта встаёт в очереди навсегда, так что форма «по умолчанию всё
   принять, совпавшее — переписать» тут несущая.
4. После вердикта fwmark стирается (`set_nfmark(0)`) — дальше по цепочке
   пакет идёт уже без внутренней марки (не зациклится на mark-правилах
   ниже, ничего не утянет в policy routing).
5. Чексуммы после переписывания всегда пересчитываются (TCP-чексумма по
   псевдозаголовку + пейлоаду, чексумма IP-заголовка). `total_len`
   обновляется через `set_payload_len`, если размер TCP-заголовка
   изменился.

Профили по маркам: обработчики очередей выбирают конфиг по fwmark пакета —
доменный оверлей с такой маркой, если есть, иначе дефолтный профиль.
Учти: доменные TCP-конфиги работают только когда задана дефолтная
`mark` (то же условие вообще стартует очереди).

## Требования

- Linux с `iptables` / `ip6tables` (таблица mangle, таргет NFQUEUE).
- Root или минимум `CAP_NET_ADMIN` (`SO_MARK`, бинд NFQUEUE, iptables).
  `CAP_NET_RAW` тоже пригодится. См. [Диагностику](#диагностика).
- Два **свободных** номера очередей. Не занимай очередь чужого инструмента
  (напр. zapret/nfqws обычно сидит на `300`) — на один номер может
  забиндиться только один процесс, второй бинд упадёт.

## Конфигурация (блок `tcp`)

```json
"tcp": {
    "mark": "0x10",
    "qnum_syn": 301,
    "qnum_tcp": 302,
    "auto_iptables": true,
    "ttl": 128,
    "window_size": 64240,
    "mss": 1460,
    "window_scale": 7,
    "dont_fragment": true,
    "timestamp": true,
    "tcp_options_order": ["mss", "sack_perm", "timestamp", "wscale", "nop"]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `mark` | hex-строка или число, опционально | `SO_MARK` для апстрим-сокетов и марка, по которой матчат iptables-правила. `"0x10"` и `16` — одно и то же. Если не задана — TCP-слой выключен целиком (очередей нет, коннекты прямые). |
| `qnum_syn` | число, опционально | Номер NFQUEUE для SYN-пакетов. Должен отличаться от `qnum_tcp`. |
| `qnum_tcp` | число, опционально | Номер NFQUEUE для пакетов установленного соединения. |
| `auto_iptables` | bool (по умолчанию `false`) | Управлять mangle-правилами автоматически (вставить на старте, удалить по Ctrl+C). |
| `ttl` | число 0–255, опционально | TTL для IPv4 (hop limit для IPv6 в `tcp`-очереди). `null` = оставить ядерное. |
| `window_size` | число, опционально | TCP window (только SYN). Кастуется к u16. `null` = оставить. |
| `mss` | число, опционально | Значение MSS, когда опция `mss` испускается. Фолбэк — ядерное значение. |
| `window_scale` | число, опционально | То же для опции `wscale`. |
| `dont_fragment` | bool (по умолчанию `false`) | Значение флага DF, записываемое в SYN-пакеты. |
| `timestamp` | bool (по умолчанию `false`) | Испускать ли TCP-опцию `timestamp` вообще. При `false` вырезается, даже если есть в `tcp_options_order`; отсутствие поля — тоже `false`, так что выставляй явно. |
| `tcp_options_order` | список строк, опционально | Пересобрать SYN-опции с нуля в этом порядке. `null` = сохранить ядерный порядок, только пропатчить значения MSS/wscale. |

### Имена в `tcp_options_order`

| Имя (алиасы) | Испускаемая опция |
|---|---|
| `mss` | Maximum Segment Size (значение `mss` или ядерное) |
| `wscale`, `window_scale`, `ws` | Window Scale (значение `window_scale` или ядерное) |
| `sack_perm`, `sack`, `sack_ok`, `sack_permitted` | SACK Permitted |
| `timestamp`, `ts`, `timestamps` | Timestamps, ядерные `tsval` / `tsecr=0` (только при `timestamp: true`) |
| `nop`, `noop` | Один NOP-байт (паддинг/выравнивание) |

Неизвестные имена игнорируются. Энкодер сам допадит опции до границы
4 байт, так что явный `"nop"` — это способ воспроизвести отпечатки вида
`mss,sack,timestamp,nop,wscale`: без него будет нулевой (EOL) паддинг и
другая сигнатура.

## Управление iptables (`auto_iptables`)

При `true` на старте прокси обеспечивает два правила на каждую
используемую марку (дефолтная + марки всех доменных оверлеев):

```
-mangle/POSTROUTING -p tcp --syn   -m mark --mark <M> -j NFQUEUE --queue-num <qnum_syn> --queue-bypass
-mangle/POSTROUTING -p tcp ! --syn -m mark --mark <M> -j NFQUEUE --queue-num <qnum_tcp> --queue-bypass
```

Нюансы, важные когда mangle делят с тобой другие (zapret/nfqws, libvirt):

- Правила вставляются **наверх** (`-I POSTROUTING 1`), выше чужих.
  Добавление в конец (`-A`) оставляет их под тем же nfqws, который
  перехватит пакеты первым — и твои увидят ноль трафика.
- Перед вставкой все существующие копии такого же правила удаляются,
  так что рестарты мигрируют правила, оставшиеся внизу от старых версий,
  и никогда не плодят дубликаты.
- `--queue-bypass` пропускает пакеты дальше, когда юзерспейс-ридер не
  забинден (прокси лежит), вместо того чтобы мариновать их в ядре.
- Та же пара зеркалится в `ip6tables` в best-effort режиме (ошибка — это
  варнинг, а не фатал).
- По Ctrl+C прокси удаляет добавленные правила (все копии) и затем
  завершается явно — петли NFQUEUE блокируют воркеры рантайма в `recv()`,
  так что обычный return из `main` повесил бы шатдаун навсегда.

При `auto_iptables: false` ничего не трогается: примени обе строки на
марку один раз руками под sudo, они живут до ребута/флаша.

## TCP-профили по доменам (`-d domain.json`)

Доменный оверлей может нести свою секцию `tcp`. Семантика мерджа: каждое
поле наследует базовое значение, пока оверлей его не задал — включая
`mark` (явный `"mark": null` её снимает). `qnum_syn`/`qnum_tcp` всегда
общие из базового профиля. Каждая distinct-марка получает свою пару
iptables-правил и свою ветку конфига в обработчиках очередей.

```json
{
    "tls.peet.ws": {
        "tcp": {
            "mark": "0x11",
            "ttl": 100,
            "window_size": 64130,
            "mss": 1400,
            "window_scale": 7,
            "dont_fragment": true,
            "timestamp": false,
            "tcp_options_order": ["mss", "sack_perm", "wscale", "nop"]
        }
    }
}
```

Важно: если базовый профиль задаёт `upstream_proxy`, **марки не
ставятся вообще** — апстрим-соединения идут `CONNECT`-туннелем до этого
прокси на обычных сокетах, так что весь TCP-слой обходится по дизайну.

## Проверка

```bash
# правила на месте, наши сверху?
sudo iptables -t mangle -S POSTROUTING
# счётчики растут под нагрузкой? (дважды, пока курлишь через прокси)
sudo iptables -t mangle -L POSTROUTING -v -n
# очереди забиндены, пакеты текут (а не залипли)?
cat /proc/net/netfilter/nfnetlink_queue
# реальный SYN на проводе совпадает с профилем?
sudo tcpdump -i any 'tcp[tcpflags] & tcp-syn != 0' -v -c 5
```

## Диагностика

- **`Permission denied (you must be root)` на `iptables -A`** —
  `nf_tables`-бэкенд хочет настоящий рут, даже когда `SO_MARK`/NFQUEUE
  работают с файловыми capabilities. Варианты: запуск под sudo / рутовым
  systemd-юнитом, либо `auto_iptables: false` + правила один раз руками.
- **Капабилити слетают после пересборки** — `cargo build` создаёт новый
  бинарник, файловые капы его не переживают. Перенакатывай
  `setcap 'cap_net_admin,cap_net_raw+ep'` после каждой сборки (проверка —
  `getcap`). На NixOS `/nix/store` read-only — только через
  `security.wrappers`. В контейнерах нужен `--cap-add=NET_ADMIN,NET_RAW`.
- **Наши правила видят 0 пакетов** — по порядку: (1) тестовый трафик
  реально идёт через *этот* прокси; (2) `upstream_proxy` равен `null`
  (иначе марки никогда не ставятся); (3) оверлей SNI-домена не сбросил
  марку; (4) счётчики `ip6tables` тоже глянь — первый ответ DNS может
  быть AAAA и трафик пойдёт по IPv6.
- **`bind(queue) failed`** — номер очереди занят другим инструментом.
  Выбери свободные (см. `/proc/net/netfilter/nfnetlink_queue`).
- **Хендшейки/`502` после включения марок** — для `SO_MARK` нужен
  `CAP_NET_ADMIN`; ошибка видна в логах как `Failed to set SO_MARK` /
  `Connection failure`.
