# mitm-proxy-ja3-ja4

[English](README.md) | [Русский](README.ru.md)

HTTP MITM-прокси, написанный на Rust с использованием `tokio` и `BoringSSL`.

> **В данный момент проект находится на стадии MVP (Minimum Viable Product).**

Проект был полностью переписан на `boring` (BoringSSL) для получения более глубокого контроля над подменой TLS-отпечатков. Сейчас он работает как прозрачный MITM-прокси с поддержкой апстрима, но подмена TLS-отпечатков пока реализована в статичном (неконтролируемом) виде.

## Возможности (Текущая реализация)

- **MITM (Man-in-the-Middle)** — Прозрачный перехват HTTPS. Сертификаты генерируются и подписываются на лету с помощью `rcgen`, а для производительности кэшируются через `dashmap`.
- **Интеграция с BoringSSL** — Для обработки TLS-хендшейка и MITM-перехвата используются `boring` и `tokio-boring`.
- **Поддержка апстрим HTTP прокси** — Возможность проксировать соединения через HTTP-прокси методом `CONNECT` (настраивается через аргументы запуска).
- **Асинхронность** — Построен на базе `tokio` для высокопроизводительного и неблокирующего асинхронного ввода-вывода.

## Планы (Roadmap)

Текущая архитектура — это фундамент для продвинутого спуфинга отпечатков:

- **Динамическая подмена отпечатков (JSON-профили)** 
  Реализация детальной и динамической подмены TLS (JA3/JA4), HTTP/2 (Akamai) и TCP-параметров. Конфигурация будет считываться из JSON-профилей (см. `example.json` в репозитории для примера структуры).
- **L4 TCP Fingerprinting (NFQueue)**
  Разработка модуля 4-го уровня с использованием очередей Linux `nfqueue` (Netfilter Queue) для подмены TCP-отпечатков: TTL, размер окна TCP, MSS, window scaling и точного порядка TCP-опций.

## Требования

- Rust (edition 2021)
- Linux (для будущих фич с `nfqueue` на L4)
- Firefox с расширением [Multi-Account Containers](https://addons.mozilla.org/firefox/addon/multi-account-containers/) (настоятельно рекомендуется для одновременного использования разных отпечатков)

## Установка и запуск

### 1. Сборка

```bash
git clone https://github.com/3Radiance/mitm-proxy-ja3-ja4.git
cd mitm-proxy-ja3-ja4
cargo build --release
```

### 2. Запуск

Вы можете запустить прокси, указав порт и (опционально) апстрим HTTP-прокси.

```bash
# Запуск на порту по умолчанию (9090)
cargo run --release

# Запуск на кастомном порту
cargo run --release -- --port 8080

# Запуск с апстрим HTTP-прокси
cargo run --release -- --upstream 127.0.0.1:10808
```

При первом запуске прокси сгенерирует файлы CA в текущей директории:
- `ca.crt` — Корневой сертификат CA. Его необходимо импортировать в Firefox (или другой браузер) и сделать доверенным.
- `ca.key` — Приватный ключ CA.

## Архитектура

- `src/main.rs`: Точка входа, использует `clap` для парсинга `--port` и `--upstream`.
- `src/proxy/tcp.rs`: Обработка TCP-соединений, парсинг начального `CONNECT`, подключение к апстриму и передача сырых сокетов в слой TLS MITM.
- `src/tls/cert.rs`: Генерация сертификатов на лету через `rcgen` и `boring::x509`, их подпись локальным CA и кэширование в `DashMap`.
- `src/tls/tls.rs`: Конфигурация акцептора BoringSSL и обработка хендшейков (`tokio-boring`).
